The created record's "userId" field is populated server-side by the REAL
Week-1 API directly from the validated token's "sub" claim
(QuoteEndpointExtensions.cs: `UserId = user.FindFirst(ClaimTypes.NameIdentifier)?.Value`)
— it is literally the Managed Identity's own Azure AD object id. This is
not something the proxy could fake; it is proof, produced by the real API
itself, that the API validated an Azure-AD/Managed-Identity-issued token
and recorded the calling identity from it.

ZERO SECRETS
------------
- day17-mi-proxy Container App: system-assigned Managed Identity only.
  `az containerapp secret list` -> empty. Env vars are all non-secret
  identifiers (API base URL, token scope/audience, allowed CORS origin).
- day-5-piece-2 Container App: `az containerapp secret list` -> empty.
  EntraId__TenantId/ClientId are public, non-secret identifiers (a tenant
  GUID and an app's client id are not credentials — they identify who to
  ask, not a secret that proves who you are; the Managed Identity itself
  is what proves identity, and it is never exposed as a value anywhere).
- Azure Static Web App: `az staticwebapp appsettings list` -> empty.
- No client secret, certificate, or connection string was created for
  either app registration or either Container App at any point.
